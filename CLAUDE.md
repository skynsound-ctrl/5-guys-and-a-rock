## What we're building
A private site for a 12-team Sleeper fantasy football league:
1. Live scoreboard + standings (client-side, straight from Sleeper's API)
2. Auto-generated articles (recaps, previews, power rankings, trade grades, injury alerts) written by the Claude API from real league data
3. Deep links back into the real Sleeper app

Visual target: NHL.com-style sports desk — dark chrome, condensed bold type, a live scoreboard rail under the nav. `league-hub-prototype.html` in this folder is a working proof of the front end and the Sleeper calls — treat it as the visual and functional reference, not throwaway.

## Architecture (decided — don't re-litigate without saying why)
**Static site + scheduled script. No database, no server, no hosting bill.**

```
site/                 static HTML/CSS/JS → served by GitHub Pages
scripts/               Python: fetch → compute facts → generate → write HTML
data/                  committed JSON snapshots (this IS the database)
.github/workflows/     GitHub Actions cron jobs
```

- Live scores: fetched client-side, straight from Sleeper, no server involved.
- Articles: generated by a scheduled GitHub Action, written to disk, committed to the repo.
- State: plain JSON files in `data/`. Diffs come from comparing snapshots week to week.

Cost: everything free except the Anthropic API (~$4–8/month).

## Sleeper API essentials
Base `https://api.sleeper.app/v1`, free, no key needed. Full endpoint table and gotchas are in the brief — the two that matter most:
- `/players/nfl` is ~5MB — fetch **once a day**, cache to `data/players.json`, never call from the browser.
- Use `display_week`, not `week` — they diverge around playoffs.

## The facts engine (`scripts/facts.py`) — not built yet
Plain Python, no AI. Reads Sleeper data, outputs a flat JSON block of verified facts (bench points, over/underperformance vs. season average, streaks, PF-rank vs. record-rank, etc.). Article quality lives here, not in the prompt.

## Article generation (`scripts/generate.py`) — not built yet
One Claude API call per article, Sonnet-class model. Hard rule baked into the system prompt: every number/name in the output must appear verbatim in the FACTS block — no inference, no invented stats. A validator regex-checks every number in generated text against the facts before anything publishes. Fail twice → don't publish, log it.

## Build order — one step at a time, stop after each
1. **Repo skeleton + prototype live on GitHub Pages.** ← we are here
2. Daily Action that caches `/players/nfl` and snapshots rosters/matchups into `data/`.
3. `facts.py` — outputs the facts JSON, no AI yet, checked by eye against Sleeper.
4. `generate.py` + validator — recaps and transaction wire, output to a review folder, not live.
5. Design pass — fonts, rail, article pages, team colors.
6. Auto-publish, once trusted for two weeks.

## Secrets
Anthropic API key goes in GitHub repo → Settings → Secrets and variables → Actions. Never in a file, never committed. `.env` goes in `.gitignore` before any code reads a key.
