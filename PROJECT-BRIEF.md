## What we're building

A private website for a 12-team Sleeper fantasy football league. It does three things:

1. **Live scoreboard + standings** pulled from Sleeper
2. **Auto-generated news articles** — recaps, previews, power rankings, trade grades, injury alerts — written by the Claude API from real league data
3. **Deep links into Sleeper** so people can jump to the real app

Visual target: a sports-desk look in the register of NHL.com. Dark chrome, condensed bold display type, a live scoreboard rail pinned under the nav. A working prototype of the front end is in this folder as `league-hub-prototype.html` — read it, it establishes the visual direction and proves the Sleeper calls work.

## Architecture (decided — don't re-litigate without telling me why)

**Static site + scheduled script.** No database, no server, no hosting bill.

```
GitHub repo
├── site/                 static HTML/CSS/JS  → served by GitHub Pages
├── scripts/              Python: fetch → compute facts → generate → write HTML
├── data/                 committed JSON snapshots (this IS the database)
└── .github/workflows/    GitHub Actions cron jobs
```

- **Live scores** run client-side in the visitor's browser, hitting Sleeper directly. Already proven in the prototype.
- **Articles** are generated by a GitHub Action on a schedule, written to disk as files, and committed back to the repo.
- **State** lives in committed JSON files in `data/`. Week-over-week diffs come from comparing snapshots. This is unglamorous and completely sufficient at this scale.

Why this shape: it survives me not touching it for three weeks. There's no server to go down, no database to fill up, no bill to forget to pay.

**Cost:** GitHub free, Pages free, Actions free at this volume. Only real cost is the Anthropic API, ~$4–8/month.

## Sleeper API — everything you need

Base: `https://api.sleeper.app/v1` — free, read-only, **no API key or auth**. Docs: https://docs.sleeper.com/

| Endpoint | Returns | Poll |
|---|---|---|
| `/state/nfl` | `week`, `display_week`, `season`, `season_type` | hourly |
| `/league/{id}` | scoring settings, roster slots, status | daily |
| `/league/{id}/users` | display names, avatars, custom team names | daily |
| `/league/{id}/rosters` | ownership, W/L, points for/against | 15 min |
| `/league/{id}/matchups/{week}` | the scoreboard | 60s during games |
| `/league/{id}/transactions/{week}` | waivers, FAAB, trades | 15 min |
| `/league/{id}/winners_bracket` | playoff bracket | weekly, Dec |
| `/players/nfl` | player ID → name/team/position map | **once daily, hard limit** |
| `/players/nfl/trending/add` | league-wide hottest adds | hourly |

### Non-obvious things that will bite you

1. **Rate limit: stay under 1,000 calls/minute per IP or you get blocked.** Ours is nowhere near it, but never let the browser poll in a tight loop.
2. **`/players/nfl` is ~5MB.** Sleeper explicitly says once per day, max. Cache it to `data/players.json` in a daily Action. Never call it from the browser. `?position=QB&active=true` filters exist and shrink it a lot.
3. **`players_points` is undocumented.** The matchups response carries `players_points` (map of player_id → score) and `starters_points` (ordered array) even though the docs only show `points`. Use them, but wrap in optional chaining with a fallback to team totals — Sleeper can drop them without notice.
4. **Points are split across two fields.** Roster settings give `fpts` and `fpts_decimal` separately. Real value is `fpts + fpts_decimal/100`. Same for `fpts_against`.
5. **Use `display_week`, not `week`.** They differ around week transitions and playoffs.
6. **Two teams share a `matchup_id`.** That's how you pair a game. A bye or odd roster count means a lone entry — handle it.
7. **Give Sleeper attribution** if we use the trending adds feed. Footer line is fine.
8. **Empty matchups in preseason is normal**, not an error. Fail gracefully.

Deep links: `https://sleeper.com/leagues/{league_id}` and `/leagues/{league_id}/matchup`.

## The facts engine (`scripts/facts.py`)

**This is the most important file in the project.** It is plain Python — no AI. It reads Sleeper data and outputs a JSON block of verified facts. Article quality is determined here, not in the prompt.

For each week compute:

- Final scores, margin of victory, and where that margin ranks among the week's games
- **Bench points** — points scored by non-starters. This is the single most reliable source of good content. "Left 38 on the bench" writes itself.
- Each starter's score vs. their own season average (over/underperformance)
- Win/loss streaks
- Points-for rank vs. record rank — surfaces who's unlucky
- Head-to-head history between this week's opponents
- Playoff seeding implications
- Biggest FAAB overpay of the week
- Highest and lowest scoring team of the week, season-to-date context

Output shape: a flat JSON object, every value a finished number or string. No nesting deeper than two levels. The generator gets this and nothing else.

## Article generation (`scripts/generate.py`)

One Claude API call per article. Model: a Sonnet-class model, ~1000 max tokens.

### The prompt contract

```
SYSTEM:
You are a beat writer covering a 12-team fantasy football league.
Register: declarative, specific, lightly wry. A national sports desk,
not a hype account.

HARD RULE: every number, name, and result in your output must appear
verbatim in the FACTS block. You may not compute, estimate, infer, or
recall any statistic. If a fact you want doesn't exist in the block,
write around it. Inventing a statistic is the only unrecoverable error.

Do not flatter the managers. Do not open with a rhetorical question.
Do not use the words "showdown", "clash", "battle", or "faithful".

FACTS:
{facts json}

TASK:
{350-word recap of matchup X. Lead with the bench-points story.}
```

### The validator — not optional

After generation, before publishing:

1. Regex every number out of the generated text
2. Assert each one appears in the input FACTS block
3. Fail → regenerate once → fail again → **do not publish**, log it, move on

Without this, week three produces an article citing a touchdown that never happened, one manager notices, and the site's credibility is gone permanently. Build the validator in the same session as the generator.

### Article types

| Type | Schedule | Hook |
|---|---|---|
| Game recap (×6) | Tue 6am | bench points |
| Weekly preview | Tue 6am | H2H history, current form |
| Power rankings | Wed | rank in Python, AI writes blurbs only |
| Transaction wire | on new transaction | trade grades get the most reads |
| Injury alert | on `injury_status` change | rostered players only |
| Waiver preview | Tue night | trending adds ∩ our free agents |
| Season awards | week 18 | the screenshot piece |

### Player news

Sleeper gives **no news text and no projections** — only `injury_status`, `injury_body_part`, `practice_participation`, and a `news_updated` timestamp.

Phase 1: diff the daily player snapshot, emit structured events ("X moved Questionable → Out"), let the AI write around them. Free, zero legal risk. This is enough to start.

Later, if needed: a paid structured news API (Tank01 via RapidAPI, FantasyNerds, SportsDataIO). **Do not scrape Rotowire, Rotoworld, or any paywalled analysis** and launder it through the model — that's a real problem, not a theoretical one. Headlines plus a link out are fine; reproducing body text is not.

## Design tokens (from the prototype)

```
--chrome   #0B0E13   dark nav and scoreboard rail
--chrome-2 #161B23   raised tiles within chrome
--page     #EEF0F4   page background
--card     #FFFFFF   article and table surfaces
--ink      #0B0E13   primary text
--ink-2    #5A6472   secondary
--ink-3    #8B95A3   muted
--rule     #DCE0E7   hairlines
--live     #D02F32   in-progress accent
--gold     #C8A24A   playoff cut line, hover
```

Display face: Barlow Condensed 600/700, uppercase, letterspaced — headlines, scores, section heads, eyebrows.
Body face: Inter 400/500.
All numbers use `font-variant-numeric: tabular-nums` so scores don't jitter as they update.

**Signature element:** the scoreboard rail. Fantasy's equivalent of a period clock is *starters yet to play* — surface that count on every tile. It's the number people actually want and no other league site shows it well.

Structural rules: eyebrow labels in condensed caps above every headline. Team accent color as a 4px left border only, never a background fill. 2px border radius — near-square, sports-desk, not consumer-app rounded.

Quality floor: responsive to mobile, visible keyboard focus, respects `prefers-reduced-motion`.
